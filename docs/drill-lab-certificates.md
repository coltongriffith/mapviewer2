# Lab certificate links

After committing an assay import, the optional **Add supporting lab certificates**
step offers **Attach lab certificates** for that exact committed batch. You can
skip it and later open **Lab certificates** on the assay import in history.
A no-op import or a replay of a rolled-back batch does not offer this step.
Starting another import or leaving the property clears the completion step.
An editor can select a PDF already in the property's data library, or upload
and link a new PDF using the existing private-library uploader. Importing assay
data stays independent: a failed certificate attachment never rolls back a
successful import. If an upload succeeds but linking fails, the UI reports this
and the file remains selectable for a retry.

Each link records the exact library file/version, the filename at linking,
SHA-256, actor and time. A newer library version or rename cannot silently
change that provenance. The certificate is supporting evidence, not a claim
that the assays have been verified against its contents.

Editors can retract an incorrect link with a reason. The original link and PDF
remain, and the retraction records its actor and time. A retracted exact
file/version cannot be reinstated in this first slice; attach the correct file
or version. Viewers can inspect/download but cannot link or retract. Rolled-back
assay batches retain certificates; new attachments to them are refused.

This slice provides batch-level links after import, including the completion
step. Pre-commit certificate selection, per-assay row links and QA/QC failure-list
links are not yet implemented. Current history displays the existing latest 50 import batches.

## Deployment and security

`20261101100000_drill_batch_certificates.sql` is additive and requires the
workspace, property-library and drill-database migrations. It was generated by
Supabase CLI, then moved after the repository's existing future-dated migration
sequence. It has **not** been applied to production. Until installed, opening
certificate controls gives a clear unavailable message; ordinary imports work.

The new table enables RLS and limits inserts to three input columns. An invoker
trigger obtains provenance from visible database records and enforces same
property/org, assay batch, current batch, PDF path and editor access. Only the
retraction reason is updateable; no client deletes or snapshot edits are allowed.
The read function is invoker, and anonymous execution is revoked. Links survive
batch rollback. Local PGlite tests apply the migration twice and exercise actual
SQL permissions, including direct writes and spoofed provenance.

Download initiation rechecks visibility and requests the pinned version with a
five-minute signed URL. Soft-deleted files retain audit metadata but return no
download path in this interface, even for admins. Existing library Storage
policies are unchanged: an already-issued URL lasts until expiry, and those
policies authorize known paths by workspace membership rather than file deletion.
This change does not claim global revocation of previously known library paths.

Local PGlite verifies database behavior, not hosted PostgREST/Storage integration.
An authorized staging migration and smoke test are needed before production
database rollout; no local Supabase/Docker advisors run is claimed.
